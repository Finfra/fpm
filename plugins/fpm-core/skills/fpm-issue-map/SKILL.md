# 목적

`Issue.md` 는 이슈를 나열하지만 **무엇이 무엇을 막고 있는지**는 텍스트만으로 파악하기 어렵다. 본 스킬은 `Issue.md` 를 단일 SSOT 로 삼아 의존 관계도·임계 경로·착수 가능 여부를 한 장의 HTML(`Issue_map.htm`)로 생성한다.

산출물은 **fPm hub 렌더물이 아니라 프로젝트에서 지속 관리되는 독립 문서**다. 다이어그램을 SVG 로 선렌더해 파일 안에 넣으므로 서버·네트워크 없이 파일 하나로 열람된다.

nPTiR(`Issue.md`)을 쓰는 **모든 프로젝트**에서 사용 가능한 글로벌 SCAR 다 (Issue246 으로 prj58 로컬에서 승격).

# 실행

**nPTiR 루트(= `Issue.md` 가 있는 디렉토리)에서 실행**한다. 생성기는 cwd 기준으로 `Issue.md` 를 읽고 `Issue_map.htm` 을 쓴다.

## 생성기 경로 해석 (`$BIM` — 플러그인·글로벌 양쪽 지원, Issue316)

본 스킬은 **글로벌 SCAR(`~/.claude/skills/issue-map/`)** 와 **fpm-core 플러그인 번들(`${CLAUDE_PLUGIN_ROOT}/skills/fpm-issue-map/`)** 두 경로로 배포된다. 경로를 하드코딩하면 플러그인 전용 설치 환경(prj1 미설치 머신)에서 파일을 못 찾아 영구 실패한다 — 아래 resolver 를 **먼저 실행**해 `$BIM` 을 확정한 뒤 그것만 호출한다.

```bash
BIM=""
for c in "${CLAUDE_PLUGIN_ROOT:-/nonexistent}/skills/fpm-issue-map/build_issue_map.py" \
         "$HOME/.claude/skills/issue-map/build_issue_map.py"; do
  [ -f "$c" ] && { BIM="$c"; break; }
done
[ -n "$BIM" ] || { echo "issue-map 생성기 없음 (플러그인·글로벌 양쪽 부재) — 중단"; exit 1; }
```

* 우선순위: **플러그인 번들 → 글로벌**. 플러그인 설치 환경에서는 번들 사본이 배포 버전이므로 우선한다.
* 둘 다 없으면 **fail-loud 중단**. 손으로 mermaid 를 쓰는 등 규격 이탈 대체품을 만들지 않는다(fg1 실측 회귀 — Issue316).

```bash
# 기본 — Issue.md → Issue_map.htm 생성
python3 "$BIM"

# 파싱 결과만 확인 (파일 미생성) — 형식 오류 진단용
python3 "$BIM" --check

# 교착(순환 대기) 진단만 출력 (파일 미생성)
python3 "$BIM" --deadlock

# 타 프로젝트를 조회하지 않음 (오프라인·속도 우선)
python3 "$BIM" --no-cross

# 경로 지정
python3 "$BIM" --issue Issue.md --out Issue_map.htm
```

생성 후 확인:

```bash
open -a Firefox "file://$PWD/Issue_map.htm"
```

# 입력 규약 (Issue.md)

파서는 글로벌 [`rules/issue-g.md`](../../rules/issue-g.md) 형식을 그대로 따른다. 확장 필드 2개(`* trigger:` · `* status:`)는 **선택**이며, 없으면 해당 표현만 생략된다 (Issue246 에서 `issue-g.md` 선택 필드로 편입).

| 요소 | 형식 | 용도 |
| :--- | :--- | :--- |
| 섹션 | `# ✅ 완료` · `# 🚧 진행중` · `# 📕 중요` · `# 📙 일반` · `# 📗 선택` | 노드 색상·상태 판정 |
| 제외 섹션 | `# ⏸️ 보류` · `# 🚫 취소` | **맵에서 제외** — 노드·표 양쪽에서 빠짐. 단 **미완료 활성 이슈가 `depends` 로 가리키는 보류·취소 이슈**는 회색 점선 유령 노드로만 남아 차단 사실을 보존 (Issue259) |
| 이슈 | `## Issue7: 제목 (등록: ...)` | 노드 생성 |
| 서브 이슈 | `### Issue5_1: 제목` | 노드 생성 + **부모 암묵 의존**(depends 미선언 시) |
| 선행 | `* depends: Issue3, Issue5` | 화살표 생성 |
| 타 prj 선행 | `* depends: prj16#Issue42` | 대상 프로젝트 `Issue.md` 를 읽어 상태 판정 후 **점선 노드로 편입** (Issue252) |
| 트리거 (확장) | `* trigger: PR #1982 merge 완료` | 그 이슈로 들어오는 화살표의 **라벨** + 전이 트리거 표 항목 |
| 상태 메모 (확장) | `* status: PR #1982 OPEN · merge 대기` | 이슈 표의 상태 칸을 이 문구로 대체 |
| 간단 이슈 마커 | `## Issue260: 제목 (!) (등록: ...)` | **해결책 미정 = 착수 불가 노드.** 지도에 올려 `depends`/`trigger` 로 엮기 위해 번호만 받은 자리표시자이며 fix 대상이 아님(Issue268). 제목 그대로 title 문자열에 남아 노드 라벨에 노출됨(파서 동작 불변). 상세 규약: `rules/issue-g.md` 규칙2 |

`* trigger:` 는 **후행 이슈**에 적는다. ex) Issue14 에 `* trigger: PR #1982 merge 완료` 를 넣으면 `Issue1 → Issue14` 화살표에 그 문구가 붙는다.

**`depends` 를 적었다면 `trigger` 도 적는 것을 권장한다** (Issue248). `depends` 는 *연결의 존재*만 말하고, `trigger` 는 *그 연결이 풀리는 조건*을 말한다. 후자가 비면 화살표는 "막혀 있다"까지만 보여주고 **무엇을 해야 풀리는지**를 사람이 매번 이슈 본문에서 재추론해야 한다. 조건은 **관측·판정 가능**하게 쓴다.

* 좋음: `* trigger: prj1#Issue286 이 ✅ 완료 + commit hash 기록됨`
* 나쁨: `* trigger: 준비되면` (누가 언제 판정하는지 불명)

# 그래프 가지치기 — 무엇이 그래프에 남는가 (Issue247)

그래프는 **서로 이어진 남은 작업만** 보여준다. 두 부류가 그래프에서 빠진다.

| 제외 부류 | 조건 | 어디로 가는가 |
| :--- | :--- | :--- |
| **정리 완료** | 자신이 완료 + 후행이 없거나 전부 완료 | **문서에서 제외** (건수만 고지 — Issue250) |
| **미연결** | `depends` 화살표가 하나도 안 붙은 **미완료** 이슈 | **진행 전 이슈** 표 + 이슈 표(`그래프` 칸 = `미연결`) |

* 완료됐지만 후행이 미완료면 그 화살표가 "지금 착수 가능"을 뜻하므로 계속 표시된다
* 고립 노드를 빼는 이유: 의존 관계도는 **무엇이 무엇을 막는가**를 답하는 그림이다. 화살표 없는 노드는 그 질문에 기여하지 않으면서 시야만 먹는다

## 이슈 표 범위 (Issue250)

이슈 표에 남는 것은 **그래프 연동분 ∪ 미완료 전량**이다. `완료 && 그래프 미표시` 행은 뺀다 — 이슈맵은 "지금 무엇이 막혀 있나"를 답하는 문서이고, 그래프와 무관한 과거 완료 이슈를 매번 수백 행 다시 그릴 이유가 없다(prj3 실측: 240행·74KB → 8행·32KB).

* **미완료는 고립이든 아니든 전량 유지** — 잔여 작업 누락 금지
* 전이 트리거 표도 같은 필터를 탄다
* 전량(감사·이력 확인)이 필요하면 `--all`
* 상단 메타 줄의 `이슈 N건 · 완료 M건` 은 **항상 전체 실태**를 보여준다

## depends 연결이 0건이면

의존 관계도·임계 경로 **섹션 자체를 생략**하고 "진행 전 이슈" 목록만 렌더한다. 이때는 `mmdc` 를 아예 호출하지 않으므로 **mermaid-cli 미설치 환경에서도 이슈맵이 생성된다**.

전량 표시(정리 완료·미연결 모두 포함)가 필요하면 `--all` 을 붙인다.

```bash
python3 "$BIM" --all
```

# 타 프로젝트 연동 · 교착 진단 (Issue252)

`* depends: prj1#Issue286` 처럼 **다른 프로젝트를 기다리는 선행**을 그래프에 편입한다. 편입 전에는 이런 이슈가 지도상 "착수 가능"으로 보였다 — 실제로는 남의 프로젝트를 기다리는 중인데도.

## 참조 표기 해석

경로 SSOT 는 `~/_git/___pm/projects/{번호}`(= 대상 경로 1줄). 아래 표기를 모두 흡수한다.

| 표기 | 해석 |
| :--- | :--- |
| `prj1#Issue286` | 번호 직접 지정 |
| `___pm#Issue99` · `.claude#Issue28` | 경로 basename 별칭 |
| `~/.claude#Issue28` | 원문 경로 별칭. **자기 prj 를 가리키면 로컬 의존으로 강등** |
| `` `___pm#Issue66` `` | 백틱 제거 후 해석 |
| `prj1 ___pm#Issue98` | 두 표기 겹침 — 마지막 토큰 채택 |
| `prj1#Issue269 (완료 — …)` | 괄호 주석은 위치 무관하게 제거 |

## 상태 판정 3값

대상 프로젝트 `Issue.md` 를 직접 열어 판정한다(프로젝트당 1회 캐시).

| 판정 | 화살표 | 의미 |
| :--- | :--- | :--- |
| ✅ 완료 | 녹색 | 선행이 끝남 → 착수 가능 |
| ⛔ 대기 | 빨강 | 선행 미완료 → 차단 |
| ⚠️ 미확인 | 회색 점선 | 대상 prj·이슈를 못 찾음 → **차단 여부 판정 불가** |

**미확인을 "착수 가능"으로 부르지 않는다.** 못 읽은 것을 안전으로 오인하면 이슈맵이 거짓 신호를 준다. 미확인은 표기 오타이거나 `~/_git/___pm/projects/` 에 매핑이 없는 prj 다.

## 교착(순환 대기) 진단

"A 가 B 를 기다리고 B 가 A 를 기다리는" 상태는 **누구도 스스로 풀 수 없다**. 이슈 텍스트만 봐서는 prj 를 가로지르는 순환을 알아챌 수 없으므로 자동 검출한다.

```bash
python3 "$BIM" --deadlock
```

* 노드 = `(프로젝트, 이슈)`, 간선 = "기다린다"(후행 → 선행). DFS 로 되돌아오는 사슬을 찾는다
* **완료된 선행은 아무도 막지 않으므로 탐색을 끊는다** — 과거의 상호 참조가 교착으로 오검출되지 않음
* 탐색 상한: 홉 3 · 프로젝트 20 (무한 탐색 금지, `opus-4-8-execution-rules.md` 준수)
* 판정 3종
    - 🔴 **교착**: 순환 검출 → 사슬을 출력. 한쪽 의존을 끊거나 이슈를 분할해야 풀림
    - 🟡 **미검출 · 미확인 있음**: 순환은 없으나 못 읽은 외부 선행이 있어 **교착 아님이 증명되지 않음**
    - 🟢 **교착 없음**: 외부 선행 전부 해석 + 순환 0건. 대기 중인 것은 **단순 대기**이며 선행 완료 시 자동 해제

## 오프라인

다른 프로젝트를 읽을 수 없는 환경에서는 `--no-cross` — 타 prj 선행을 조회하지 않고 승격 전 동작(로컬 의존만)으로 되돌아간다.

# 단계 그룹 (선택)

프로젝트 루트 기준 `data/issue_stage_map.json` 이 있으면 이슈를 로드맵 단계별 subgraph 로 묶는다. **없으면 그룹 없이 평면 렌더**(대부분의 프로젝트가 이 경우 — 파일을 만들 의무 없음).

```json
{
  "1단계 · AI 프로젝트화": ["Issue2", "Issue3", "Issue4"],
  "2단계 · JSON Formatter": ["Issue5", "Issue5_1", "Issue5_2"]
}
```

단계를 쓰는 프로젝트는 정의 출처를 자기 `_doc_arch/` 로드맵 문서에 두고, 이슈가 추가되면 이 파일에도 배치를 추가한다(누락 이슈는 그룹 밖에 그려지므로 즉시 눈에 띈다).

# 산출물 구조

`Issue_map.htm` 은 주석 마커로 구획된다. 재생성 시 **메모 구간만 보존**되고 나머지는 전량 교체된다.

| 마커 | 내용 | 재생성 시 |
| :--- | :--- | :--- |
| `ISSUE-MAP:GRAPH` | 전체 의존 관계 SVG (연결 0건이면 사유 안내문으로 대체) | 교체 |
| `ISSUE-MAP:CRITICAL` | 임계 경로 SVG (미완료 최장 사슬 자동 계산). **연결 0건이면 섹션 부재** | 교체 |
| `ISSUE-MAP:CROSS` | **타 프로젝트 연동** 표 + 교착 진단 결과 | 교체 |
| `ISSUE-MAP:PENDING` | **진행 전 이슈** 표 (미연결 미완료 이슈) | 교체 |
| `ISSUE-MAP:TRIGGER` | 전이 트리거 표 | 교체 |
| `ISSUE-MAP:TABLE` | 이슈 표 (그래프 연동분 ∪ 미완료) + 생략 건수 고지 | 교체 |
| `ISSUE-MAP:NOTES` | **수기 메모** | **보존** |

따라서 사람이 덧붙일 해설·병목 분석은 반드시 `ISSUE-MAP:NOTES` 구간 안에 쓴다.

* **mmdc** (`@mermaid-js/mermaid-cli`) — mermaid → SVG 선렌더. **선택 의존**(Issue317) — 미설치면 `npx -y @mermaid-js/mermaid-cli` 로 자동 대체하므로 node/npx 만 있으면 동작한다. 첫 npx 실행은 패키지 다운로드로 수 분 소요 가능(timeout 600s). 상시 사용하면 `npm i -g @mermaid-js/mermaid-cli` 로 전역 설치가 빠름

# 제약

* 파서는 `Issue.md` 의 **형식 규약을 신뢰**한다. 헤더 레벨·필드명이 규약에서 벗어나면 해당 이슈가 누락되므로, 이상하면 `--check` 로 먼저 파싱 결과를 확인할 것
* **자기 파싱은 엄격, 타 prj 조회는 관용** (Issue368) — 남의 repo 포맷을 강제할 수 없고, 실재하는 이슈를 "없음" 으로 판정하면 차단 여부가 미판정으로 남아 더 나쁘다. 타 prj 조회에만 ① 제목 구분자 `.` 허용(`## Issue308. 제목`) ② 섹션 헤더 접두 일치(`# ✅ 완료 (아카이브 — …)`) ③ **아카이브 fallback**(`_doc_work/{issue,Issue}_OLD.md`, 활성에 없는 키만 보충)이 적용된다. 자기 `Issue.md` 는 종전대로 콜론·정확일치만 인정하므로 규약 이탈이 눈감아지지 않는다
* 이슈 50건을 넘어가면 단일 그래프 가독성이 떨어진다. 그 시점에는 단계별 분할 렌더를 검토
* `Issue.md` 가 없는 디렉토리에서 실행하면 즉시 실패한다 — nPTiR 루트에서 실행할 것
